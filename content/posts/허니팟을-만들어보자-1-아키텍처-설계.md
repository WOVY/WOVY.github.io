## 계기

요새 공급망 공격 탐지 프로젝트도 하고 이것저것 공부하면서 개인 프로젝트를 하나 본격적으로 하고 싶어서 주제를 생각해 봤습니다. 보안을 공부하며 지식을 쌓다 보니 IT에서 가장 중요한 건 로그가 아닐까 하는 생각이 들었습니다. 로그를 보면 동작하는 SW에 대한 대부분을 알 수 있으니까요. 

여기서 문제는 로그를 어떻게 쌓는가였습니다. 다양한 로그를 쌓으려면 실제 사용자들이 드나드는 서비스를 만들어야 할 텐데 그런 서비스를 뚝딱하고 만드는 건 쉽지 않습니다.

그때 뇌리를 스친 게 작년 ComGraduation이라는 프로젝트였습니다. 그 프로젝트에서 저의 미니 PC와 Cloudflare를 이용해 서비스를 배포했었습니다. 그때 트래픽을 보니 정말 각국에서 많은 요청들이 들어오는 걸 보고 참 신기해했던 경험이 있습니다. 거의 다 봇일 것으로 생각합니다. 그래서 저는 이 수많은 봇들이 보내는 요청을 이용해 보기로 했습니다.

격리 설계, 로그 파이프라인 구축, 탐지 룰 작성까지 SIEM 운영의 전 과정을 압축해서 경험해 보는 것이 제 목표입니다.

## 기술 스택

Claude와 대화하면서 스택을 하나씩 정했습니다. 최종 구성은 다음과 같습니다.

| 영역 | 선택 |
| --- | --- |
| 허니팟 소프트웨어 | Cowrie (SSH/Telnet 에뮬레이션) |
| 배포 환경 | Oracle Cloud Always Free (Ampere ARM, 1 OCPU/6GB) |
| OS | Ubuntu Server LTS |
| 배포 방식 | Docker / docker-compose |
| 로그 스택 | ELK (Elasticsearch, Logstash, Kibana) |
| 탐지 | Sigma 룰 + Kibana Alerting |
| 알림 | Slack |

이 중 일부는 후에 고도화 작업으로 변경될 수도 있습니다.

## 아키텍처

가장 중요하게 다룬 부분은 격리입니다. 공격 표면(Cowrie)과 분석 자원(ELK)을 물리적으로 분리했습니다.

```plain
인터넷 공격자
  → Oracle Cloud VM (Cowrie)
  → WireGuard 터널
  → 홈랩 게이트웨이 VM
  → 격리된 내부망
  → ELK VM
  → Kibana / Sigma 탐지 → Slack 알림
```

Oracle VM은 미끼 역할만 하고 무거운 연산(Elasticsearch, Logstash)은 집에 있는 Proxmox 홈랩에서 처리합니다. 클라우드 프리티어 인스턴스 하나로 ELK까지 돌리기엔 리소스가 부족하다고 생각해서 홈랩을 사용하기로 했습니다.

가장 중요한 건 인터넷에 노출된 자산이 홈 네트워크 내부망에 바로 연결되면 안 된다는 것입니다. 그래서 WireGuard P2P 터널과 전용 게이트웨이 VM을 하나 더 두었습니다. 이미 Proxmox 호스트에 Tailscale이 있어서 그걸 확장하는 방법도 고려했습니다. 그러나 정책으로 막는 것보다 구조적으로 경로를 없애는 쪽이 더 안전하다고 판단해서 별도 게이트웨이를 뒀습니다.

관리용 SSH도 퍼블릭에 열어두지 않습니다. 진짜 sshd는 WireGuard 터널 인터페이스에만 바인딩하고 관리 접속은 항상 터널을 경유합니다. 인터넷에서는 Cowrie가 흉내 내는 가짜 SSH 포트만 보입니다.
